# Backtracking Arena — Player Guide 🎮

Welcome to the **Backtracking Arena**! This guide covers everything you need to know to compete, explore the black-box problems, write your solutions, and climb the leaderboard.

---

## 1. What is Backtracking Arena?

Backtracking Arena is a unique reverse-engineering and algorithmic coding competition. 

Unlike traditional competitive programming platforms where you are handed an explicit problem statement and strict algorithm constraints, in Backtracking Arena:
- **The exact algorithm is hidden inside a "Black Box".**
- You are given an **interactive terminal** where you can send inputs and immediately observe the corresponding outputs generated by the black box.
- By probing the black box with different inputs, edge cases, and patterns, **you deduce the underlying logic/pattern**.
- Once you deduce the rule, you write a **C program** (or function) that matches the black box's behavior across all cases, including secret hidden test cases.

## 2. Workspace Layout

When you open any problem card in the arena, your screen is divided into two primary sections:

```
+------------------------------------+------------------------------------+
|                                    |                                    |
|       BLACK-BOX TERMINAL           |           CODE EDITOR              |
|                                    |                                    |
|  - Input parameter spec & bounds   |  - LeetCode-style function stub    |
|  - Interactive prompt              |  - C language syntax highlighting  |
|  - Real-time probe execution       |  - Compile & Submit button         |
|  - History of test inputs/outputs  |  - Real-time test results panel    |
|                                    |                                    |
+------------------------------------+------------------------------------+
```

- **Left Side — Blackbox Terminal:** Your interactive laboratory. Experiment with inputs, observe outputs, and test hypotheses.
- **Right Side — Code Editor & Verdict:** Where you write your C code, submit it to the automated judge, and view test results.

---

## 3. Using the Blackbox Terminal

### Sending Inputs
1. Look at the top bar of the terminal to see the **Input Specification** (e.g., `Input: int n (1 <= n <= 10)`).
2. Click the prompt field at the bottom of the terminal.
3. Type the input value(s) separated by spaces or newlines (e.g., `3` or `4 2`).
4. Press **Enter** or click **Send Probe**.
5. The output produced by the hidden reference solution will appear in the terminal window.

### Probe Limits & Cooldowns
To maintain server performance and prevent brute-force attacks:
- **Cooldown:** There is a **3-second cooldown** between probes. The terminal will display a countdown timer until you can probe again.
- **Probe Quota:** Each contestant has up to **100 probes per problem**. Spend them wisely!
- **Session History:** Your probe history is saved in your browser session for each problem, so you won't lose your notes if you switch tabs.

## 4. Writing Your Solution

### Function Mode (LeetCode-Style)
Most problems use **Function Mode**. You only need to write the logic inside the provided function stub:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdbool.h>

// You only need to implement the function below.
// Helper functions and global variables are allowed above this function!

void solve(int n, int k) {
    // Write your logic here.
    // Print the expected output to standard output (printf).
}
```

- **No `main()` needed:** The arena's automated judge wraps your code with a hidden `main()` driver that handles input reading (`scanf`) and invokes your function.
- **Helper functions:** You can declare recursion helpers, arrays, and standard headers above the function.
- **Full Program Mode:** If a problem does not use function mode, you will write a standard C program with `int main(void)`.

## 5. Submitting & Understanding Verdicts

When you feel confident that your code matches the black box, click **Submit Code**.

Your code is compiled and executed in an isolated Linux sandbox against:
1. **Sample Cases:** The example cases. If these fail, you will see your actual output vs. expected output.
2. **Hidden Test Cases:** Secret cases covering edge cases, large inputs, and boundary conditions.

### Verdict Types
| Verdict | Meaning | What to do |
|---|---|---|
| **Accepted (AC)** | All test cases passed! Full points awarded. | Celebrate and move to the next card! |
| **Wrong Answer (WA)** | Output did not match expected output on one or more tests. | Check your logic, edge cases (e.g., n=0 or n=1), and output formatting. |
| **Time Limit Exceeded (TLE)** | Code ran longer than the allowed time limit (typically 2.0s). | Optimize your recursion, prune invalid branches earlier, or avoid infinite loops. |
| **Runtime Error (RE)** | Code crashed (segmentation fault, division by zero, stack overflow). | Check array bounds and recursion base cases. |
| **Compile Error (CE)** | GCC failed to compile your program. | Click on the error message to view the compiler warnings and errors. |

## 6. Scoring and Leaderboard

- **Partial Credit:** You earn points proportionally based on the percentage of test cases passed.
- **Best Score Retained:** Your highest score on each problem is kept. Submitting an attempt that scores lower will never decrease your score.
- **Tie Breaking:** If two contestants have the same total score, ties are broken by **time of earliest submission** achieving that score.
- **Live Leaderboard:** The leaderboard updates in real-time. Keep an eye on your rank!

## 7. Tips & Strategy

1. **Start Small:** Begin your probes with the smallest valid inputs (e.g., `0`, `1`, `2`). Notice base cases and starting patterns.
2. **Count Output Lines:** Count how many lines or elements are output for each input. Often, line counts correspond to mathematical series:
   - $2^n$ -> Binary decisions / Subsets
   - $n!$ -> Permutations
   - $\binom{n}{k}$ -> Combinations
   - Fibonacci or Catalan sequences -> Constrained paths / Parentheses
3. **Inspect Output Ordering:** The exact sequence of rows printed tells you the order of recursive calls (e.g., choosing `0` before `1` vs `1` before `0`).
4. **Pruning & Base Cases:** Backtracking relies on terminating branches early when constraints are violated. Always define clear base cases.
5. **Watch the Clock:** Don't get stuck on one card for too long. If one card is tricky, explore another card and return to it later.

Good luck, and happy hacking!
